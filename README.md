# 0. О проекте.

**OVGUE** — проект, который посвящён связке OpenWrt + VirtualBox + USB Enternet +  Rouret №2.

- ⚠️ *Это независимый проект. Он не связан с оригинальным проектом OpenWrt, не создан им и не одобрен им.*

- ⚠️Перед каким либо взаимодействием с данным проектом, [вы должны прочитать "DISCLAIMER"](https://github.com/Costodoston-Work/OVGUE/blob/main/DISCLAIMER.md).

В нём мы будем рассматривать такой стек:

```
Router 1 (Основной)
      │ (интернет-кабель RJ45 №1)
      ▼
[Физ. сетевая карта CachyOS (Arch-based)] ── Адаптер 1 (мост) ──┐
                                                ▼
                                          OpenWrt (ВМ)
                                                │
                                    USB-проброс UE300 (eth1, LAN 192.168.1.1)
                                                │ (интернет-кабель RJ45 №2)
                                                ▼
                                      Router 2 (LAN-порт, DHCP off, IP 192.168.1.2)
                                                │
                                          Wi-Fi / LAN
                                                ▼
                                          Ваши устройства
```

- **То есть у нас есть:**
	- Основной роутер, который принимает интернет от провайдера.
	
	- От него протянут интернет-кабель **RJ45**, вторым концом подключённый к ПК. В данном случае на нём стоит **Arch-based система CachyOS**.
	
	- К ПК подключена внешняя USB сетевая карта. В данном случае это **Tp-Link UE300**.
	
	- От к ней подключён второй интернет-кабель.
	
	- Этот кабель вторым концом подключён к второму роутеру, который мы превратим в заглушку. Это будет чистая Wi-Fi точка доступа, не более. Вся нагрузка будет идти именно в Virtual Box OpenWrt и передавать какие-либо изменения в сети роутеру №2, с помощью внешней сетевой карты.

# 1. Установка

Нужен образ **`openwrt-24.10.8-x86-64-generic-squashfs-combined.img.gz`**.

Именно его я разбираю в проекте. **НО**, вероятно предыдущие или более позднее не должны сильно отличатся. В OpenWrt 25, например, установщик пакетов **opkg** был заменён на **apk**. Подробнее почитайте на форумах и сайтах.

**Ссылка на скачивание образа:** https://downloads.openwrt.org/releases/24.10.8/targets/x86/64/

**Прямая ссылка на загрузку:** https://downloads.openwrt.org/releases/24.10.8/targets/x86/64/openwrt-24.10.8-x86-64-generic-squashfs-combined.img.gz

# 2. Подготовка к установке OpenWrt.

### 2.1. Подготовка образа диска в правильном формате.

Мы должны конвертировать img.gz формат диска OpenWRT в валидный для VirtualBox формат .vdi. Пишем команду в терминале:
```bash
cd /ваша/рабочая/папка
VBoxManage convertfromraw openwrt-24.10.8-x86-64-generic-squashfs-combined.img openwrt_24_10_8.vdi
```

Расширим диск openwrt_24_10_8.vdi до какого-то количества MB. Я возьму оптимальное для себя значения в размере 2048 MB:
```bash
VBoxManage modifyhd ваш/путь/до/.vdi --resize 2048
```

# 5. Настройка OpenWrt.

### 5.1. Поясню про все сетевые интерфейсы простыми словами.

- **"eth0"** - отвечает за доступ к внешнему интернету из виртуальной машины.
	
- **"eth1"** - отвечает за вашу внешнюю сетевую карту. Она будет передавать весь трафик с OpenWrt второму роутеру.
	
- **"lo"** - это виртуальный сетевой интерфейс, который система использует для «общения с самой собой». Через него работают различные локальные службы.

### 5.2. Настройка eth0. Доступ в интернет.
```bash
uci del_list network.@device[0].ports='eth0'
uci set network.wan=interface
uci set network.wan.device='eth0'
uci set network.wan.proto='dhcp'
uci commit network
/etc/init.d/network restart
```

После этого **eth0** должен получить параметр **inet**.  Если **inet** нет, но пинг пошёл (смотрите ниже), то всё в норме.

Проверить можно по команде:
```bash
ip link
```

После проверяем доступ в интернет:
```bash
ping 8.8.8.8
```

Если байты пошли - WAN интернет заработал.

### 5.3. Ставим драйвер для вашей сетевой карты.

```bash
opkg update
opkg install kmod-usb-net-rtl8152
```

❗У вас драйвер может быть другой. Зависит от карты. Драйвер под неё ищите в интернете.

### 5.4. Настройка eth1. LAN.

```bash
uci set network.lan.device='eth1'
uci set network.lan.proto='static'
uci set network.lan.ipaddr='192.168.1.1'
uci set network.lan.netmask='255.255.255.0'
uci commit network
/etc/init.d/network restart
```

При применении настроек, поле ребута, проверьте наличие вашей сетевой карты в OpenWrt (**eth1**), через `ip link`. Если вы не нашли её, то перезапустите машину и перевоткните карту. Она должна появится при запуске. 
# 6. Настройка второго роутера.

*(Настройка зависит от роутера)*

- Отсоеденяем основной интернет кабель, подсоеденяем кабель от второго роутера, чтобы быть в одной локальной сети.
- Кабель от UE300 -> в **LAN-порт** второго роутера (не WAN).
- Подключаемся к админ панели роутера по адресу **`192.168.1.1`** или другой Local IP, смотря какой роутер.
- В панели нам нужно: **отключить DHCP**, сменить IP управления на **`192.168.1.2`**, или другой (смотрите чтобы не было пересечений). Сохранить, перезагрузить.

# ❗ 7. Как подключатся к роутеру?

### 7.1. Нюансы подключения в этой схеме.
Если кратко, я пока не нашёл как подключаться к LuCi или к роутеру для управления им через основной ПК.
##### Почему?
Дело в том, что ПК это неотъемлемая часть цепочки. Чтобы подключатся к админ панели OpenWrt, вы должны быть в одной локальной сети с этими панелями/устройствами. Но так, как у вас 2 роутера, вы по сути создаёте 2 локальные сети. ПК берёт интернет от провайдера. Второй роутер и сетевая карта по сути создают вторую локальную сеть, которая не связана с основной.

 Чтобы получить доступ к админ панелям, вам нужно  подключиться к той же Wi-Fi точке, которую создаёт второй роутер (Router №2). Именно тогда, вы сможете управлять панелями. Если вы попытаетесь подключится к этой точке с основного ПК по "свистку"/Wi-Fi донглу, то ПК перестанет получать интернет от основного роутера (провайдера) -> интернет не получит и OpenWrt в Virtual Box -> интернет не получит второй роутер (Router №2) -> цепь не заработает.

Поэтому, заходите в админ панели из любых других устройств, подключённых к созданной Wi-Fi точке.
